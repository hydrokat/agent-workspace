# t-007: Status tab: progress, sessions/claims, codebases, worktrees, branches

## Description
Build the Textual status app that runs in the bottom pane, with two tabs, **Status** and **Queries** (Queries in t-008). The Status tab shows, live:
- **In progress**: running sessions (cli, role, model, column/tab, current task, heartbeat age), active claims, stale warnings, and `specs/in-progress.md` entries
- **Progress per phase**: done/total per `specs/p-###-*/impl.md` (and legacy `phase-XXX`), with an expandable per-task status list
- **Codebases**: from `codebase-symlinks/` + `knowledgebase/context-history/codebase-map.md`
- **Worktrees & branches**: `git worktree list --porcelain` and current branch per codebase and for the workspace
- **Conflicts**: overlapping Affected Paths between claimed tasks (from t-004 metadata)

## Implementation Notes
Changed files (`agent-workspace-package/tandem`): NEW `src/tandem/{sanitize,snapshot}.py`, `src/tandem/sources/{specs,inprogress,gitinfo,codebases,conflicts}.py`, `src/tandem/status/{render,app}.py`; tests `test_sources.py`, `test_status_render.py`, `test_status_app.py`.

Decisions:
- Task status precedence: `t-###.md` `## Status` checked line, then the `impl.md` Timeline `(Status)` suffix, then the checkbox. Both `p-###-*`/`t-###` and legacy `phase-###`/`task-###` layouts work. Reads are capped at 1 MB with `errors="replace"`; unreadable or missing `impl.md` becomes a `WARNING` row and the other phases still render.
- `specs/in-progress.md` entries are parsed from `###` headings plus `- **Key:** value` bullets; the template's example entries (IDs `abc-1234`, `def-5678`) are skipped because the template appends real entries below its `## Example` heading.
- Git facts come from three argv `git` calls with a timeout (default 3 s in the UI, 5 s elsewhere); any failure yields `None`, shown as "Not a git repository, or git is unavailable".
- Collection runs in a worker thread every 2 s (simple polling; file watching deliberately not added: a 2 s poll over a handful of small files is cheap and portable). The UI thread never touches git.
- All untrusted text (spec titles, session fields, query text) passes through `sanitize.clean` (strips CSI/OSC/ESC and control chars). `Static` markup in untrusted content is not interpreted because content is passed as plain text updates after cleaning.
- Conflicts: normalized path equality or directory-prefix containment between claims' `paths`, reported per task pair.
- `g` focuses the highlighted session's pane via `select-pane`, only when its recorded pane id matches `^%\d+$`.
- Compact mode (< 8 rows) hides the body and keeps the summary line.
- Words accompany every symbol (`heartbeat 12s ago`, `WARNING stale`), so `NO_COLOR` and screen readers lose nothing.

# t-001: Enforce security_invoker RLS and least-privilege grants on public.user_points_summary

## Description
Remediate the Supabase Security Advisor `security_definer_view` vulnerability on `public.user_points_summary`. Because `supabase/migrations/20260430000000_user_points_summary_view.sql` created `user_points_summary` without `security_invoker = true` and `20260426190308_fix_permissions_and_schema.sql` configured default table/view privileges for `anon` and `authenticated`, any `authenticated` user (and `anon`) can query `/rest/v1/user_points_summary` as view owner `postgres` (`BYPASSRLS`) and read every user's `(user_id, total_points)` summary, bypassing `point_transactions` RLS.

Create a new append-only atomic migration `supabase/migrations/20261026000000_enforce_rls_user_points_summary_view.sql` that enables `security_invoker = true` on `public.user_points_summary`, revokes all privileges from `PUBLIC` and `anon`, revokes non-`SELECT` privileges from `authenticated`, and grants `SELECT` strictly to `authenticated` and `service_role`. Update `app-src/lib/supabase/database.types.ts` so `public.Views.user_points_summary` is typed, and verify via both static migration contract tests and a local Supabase RLS integration test.

## Requirement Classification
- **Type**: Bug Fix
- **Rationale**: Fixes an authorization/RLS bypass (`security_definer_view`) where `public.user_points_summary` executed with owner (`postgres`) privileges instead of enforcing `point_transactions` RLS per querying user.
- **Regression Risk**: Low - `app-src` currently reads cached `profiles.points` via `getUserTotalPoints()` and `getIndividualLeaderboard()`, while underlying `point_transactions` already grants `SELECT` to `authenticated` with `auth.uid() = user_id` and `is_admin()` RLS policies.

# t-005: Enable and verify production builds through the Docker Compose prod container

## Description
Harden and verify the `prod` service in `codebase-symlinks/task-tracker-web/docker-compose.yml` so a full Next.js production build and production server boot succeed reliably on Node.js 26 Active LTS — both as a one-shot build command (`docker compose run --rm prod npm run build`) and as a running container (`docker compose up -d prod`).

Right now, running a production build through `prod` faces four concrete failure modes:
1. **Host vs. Alpine `musl` `node_modules` collision**: `./app-src:/react-app` bind-mounts host `node_modules` (e.g. macOS `darwin-arm64` SWC, `@tailwindcss/oxide`, and `lightningcss` binaries) directly into `node:26-alpine` (`linux-musl`), or lacks `node_modules` entirely on a clean checkout when `prod` is invoked directly.
2. **Alpine native binary compatibility**: Prebuilt Rust/C++ binaries (`@next/swc-linux-*-musl`, `@tailwindcss/oxide`, `lightningcss`, `@sentry/cli`) benefit from `libc6-compat` in an Alpine image, and `.github/workflows/staging.yml` already runs `docker compose build --parallel`.
3. **Build-time toolchain availability**: `next build` requires `tailwindcss`, `@tailwindcss/postcss`, and `typescript` (in `devDependencies`), so container bootstrap before `npm run build` must install dev build dependencies (`npm ci --include=dev`) when `node_modules` is missing or out of sync with `package-lock.json`, and provide non-secret local fallback env defaults when `.env` is absent (per `environment-and-config.md` Rule 3).
4. **Hardcoded port `80:3000`**: `ports: - 80:3000` collides on hosts where port `80` is already bound; parameterizing `${PROD_PORT:-80}:3000` preserves `80:3000` for `staging.yml` while allowing conflict-free local `PROD_PORT` verification.

## Requirement Classification
- **Type**: Enhancement
- **Rationale**: Makes production builds and `next start` execution via the `docker-compose.yml` `prod` service self-contained, cross-platform safe, and end-to-end verified on Node 26 LTS while preserving existing `staging.yml` deploy semantics.
- **Regression Risk**: Medium - Changes to `docker-compose.yml` volumes, image build, and `prod` entrypoint affect both local Docker workflows (`react-app`, `npm`, `npx`, `prod`) and remote staging deployment (`staging.yml:112-115`).
